# Human Design deck conventions

The `human-design-reading` repo (`NIKO-999/human-design-reading`) has no
golden-standard doc of its own. Its card JSON references a `Rules.md` that is
not in the repo. These conventions are reconstructed from the content that
exists — treat them as observed practice, and if a `Rules.md` ever turns up,
it wins.

## It is the same voice family

`content/cards/sample-batch.json` carries fields named `hook`,
`livedExperience`, `origin`, `threshold`, `reframe`, `permission`,
`reflection`. That is precisely the seven-beat emotional arc in
`docs/GOLDEN-STANDARD-PART-2.md` of the main site, turned into a schema. The
shipped decks collapse that arc into a single flowing `body` rather than
labelled beats, but the arc is still what the prose walks through.

So: **read `docs/GOLDEN-STANDARD-PART-2.md` before writing here.** The address
rules, the validate→illuminate→invite spine, the 85/15 ratio, the certainty
resolution and the systems-stay-separate rule all carry over unchanged.

What does *not* carry over is the four-field Destiny Matrix structure or the
five-field Gene Keys structure. Human Design blocks are `label` + `body`.

## Structure

`content/cards/*.json`, each a `_note` plus one or more arrays of blocks.
`server/src/content.ts` indexes them; `server/src/assembly.ts` selects blocks
against a computed chart. A block is keyed by `blockId` and reached only when
the chart selects it.

| File | Group key | Blocks | Typical body | Notes |
|---|---|---|---|---|
| `part1.json` | `blocks` | 27 | ~350 chars | 9 centers × defined/undefined/open |
| `part2.json` | `authorityBlocks` | 7 | ~1400 chars | one per authority; 5 seated in a center, `mentalEnvironmental` and `lunar` have no home center |
| `part2.json` | `notSelfBlocks` | 9 | ~350 chars | per-center fallback when no seated authority applies |
| `part3-gates.json` | `blocks` | 64 | ~100 chars | one line, near-aphoristic |
| `part3-channels.json` | `blocks` | 72 | ~200 chars | |
| `part3-open.json` | `blocks` | 9 | ~350 chars | open-center readings |
| `circuits.json` | `blocks` | 27 | ~650 chars | |
| `planets.json` | `blocks` | 13 | ~1000 chars | |
| `type.json` | `blocks` | 5 | ~1000 chars | + `domains` |
| `profile-lines.json` | `blocks` | 6 | — | `conscious` / `unconscious` instead of `body`, + `domains` |

**Match the length band of the file you are writing into.** A 400-character
gate line is as wrong as a 40-character type card. The bands above are not
arbitrary — they track how much screen the assembled reading gives each block,
and a block that overruns its band unbalances the whole card.

## `domains`

`type.json`, `part2.json` authority blocks and `profile-lines.json` carry a
`domains` object: Career, Relationships, Money, Mindset, Body — the same
mechanic re-read through five lenses, selectable as tabs.

Per the `_note` in those files, each domain passage runs **two paragraphs**:
the mechanic itself, then a direct trust-versus-override contrast — what it
costs to override it in that domain, versus what changes when you actually
trust it.

Domains are the highest-risk place for the position rule. Five lenses on one
mechanic is exactly the setup where five lightly-reworded paragraphs happen.
Career and Money in particular collapse into each other unless Career is about
work as identity and contribution, and Money is about exchange and security.

## `reusedFrom`

Some blocks carry `"reusedFrom": "reference-user-deck"` — extracted near-verbatim
from an earlier deck because they were already written generically enough. It is
a provenance marker, not a quality signal. When revising a `reusedFrom` block,
either genuinely rewrite it and drop the marker, or leave it alone. Editing it
halfway while keeping the marker makes the provenance a lie.

## Grounding

`data/*.json` — `gates.json`, `channels.json`, `centers.json`, `types.json`,
`authorities.json`, `profiles.json`, `circuits.json`.

The convenient read is `content/slots.json`: 142 slots (64 gates, 36 channels,
18 centers, 12 profiles, 5 types, 7 authorities), each with its keynotes and
center already joined, generated by `content/scripts/enumerate_slots.py`.

Human Design has real mechanical doctrine — a gate belongs to a specific center
and circuit, an authority follows a definite hierarchy. Getting that wrong is a
factual error, not a stylistic one, and unlike the Destiny Matrix material there
is an established body of doctrine to be wrong about. Check `slots.json` before
asserting any mechanic.

## Checking

The blocks are `label` + `body` rather than a fixed field shape, so run the
checker in generic mode for the voice rules:

```bash
python3 <skill>/scripts/check.py --profile generic content/cards/part1.json
```

That covers hedging, third-person address, list markers, prediction language
and duplicate openers across the set. Sentence-count and field-shape checks do
not apply here — length is governed by the band table above, which the checker
reports so you can eyeball it.
